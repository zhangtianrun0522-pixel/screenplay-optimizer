# SKILL.md: screenplay-optimizer

## 工具信息
- **工具名**: screenplay-optimizer
- **功能**: 短剧剧本诊断与优化工具

## 执行流程

### Step 1：结构扫描
读入剧本/大纲，输出全局地图，包含以下要素：
- **集数段落结构**：梳理整体集数与段落切分
- **主要阻力类型识别**：标记内部/关系/外部阻力分布
- **情绪波形走势**：标记高张力/中等/低张力段落
- **重点标记位置**：标记疑似问题点

**交互规则**：
输出全局地图后进入对话模式，允许用户纠正或补充。**仅当用户明确回复"确认"后**，方可进入 Step 2。

### Step 2：四层诊断
用户确认后自动执行完毕，中途不暂停。按顺序输出以下五项内容：

1. **钩子系统诊断**：0-25分评分 + 具体问题定位到集/段
2. **节奏地图诊断**：0-25分评分 + 具体问题定位到集/段
3. **Chemistry说服力诊断**：0-25分评分 + 具体问题定位到集/段
4. **高燃场面结构诊断**：0-25分评分 + 具体问题定位到集/段
5. **总分汇总**（满分100分）

### Step 3：优先级行动清单
将所有诊断出的问题按"修改后收益最大"原则进行降序排序。
每条问题必须严格遵循以下格式输出：
`[问题位置] + [问题描述] + [修改方向] + [预期收益]`

### Step 4：Word文件输出
基于原始剧本生成标注版 `.docx` 文件，使用 `python-docx` 实现并遵循以下规范：
- **原文处理**：原文完整保留，段落结构和格式不变，不新增多余空行
- **新增建议**：使用蓝色字体插入
- **删除/替换建议**：使用红色删除线标出原文本
- **注释说明**：使用黄色高亮 + 页面批注（Comment）
- **字体规范**：中文字体设为"宋体"，英文字体设为"Times New Roman"

## 进化机制
- **项目记录**：每个项目完成后，在 `history/project-log.md` 追加复盘记录。
- **规则迭代**：每积累三条复盘记录后，检查 `core/scoring-rubric.md` 评分标准，更新相关规则，并执行 `git commit`。
- **回滚条件**：若更新后的规则在实际诊断中产生明显错误判断，立即执行 `git revert` 回滚至上一稳定版本。
